# Прогнозы up/down: проверка гипотезы «ставка на разворот по ~50x»

## Зачем
В Binance-прогнозах (5m/15m up/down относительно цены открытия окна) коэффициент
плавает вместе с ценой. Гипотеза: после сильного ухода цены от таргета ставка на
разворот по ~50x выигрывает достаточно часто (≥1/50 + маржа), чтобы быть в плюсе
при ставке $1. Результат — ответ «есть преимущество / нет» и основа признаков для
будущего ML.

## Цели / не-цели / анти-цели
- Цель: реальная вероятность разворота как функция (время до конца окна, дистанция
  до таргета), с доверительными интервалами и устойчивостью во времени.
- Цель: записать реальные коэффициенты площадки, чтобы сравнить с вероятностью.
- Не-цель сейчас: автоставки, ML-модель (следующий этап, на тех же признаках).
- Анти-цель: «найти» преимущество подгонкой под историю или без реальных коэффициентов.

## Подходы
- A (выбран): таблица вероятностей по 1m-свечам + ручные/записанные коэффициенты.
- B: 1s-свечи с data.binance.vision — шаг 2, если A покажет интересное.
- C: сразу ML — отложен: без преимущества в A модель найдёт шум.

## Часть 1 — `cmd/predict` (история)
- Данные: спот 1m klines (`LoadHistoricalSpotCandles`), BTCUSDT + ETHUSDT (флаг
  `-symbols`), 2 года (флаг `-days`), JSON-кэш как в `cmd/regime`.
- Окна 5m и 15m по UTC-сетке; таргет = open окна. Точки входа — конец каждой
  минуты k = 1..N-1.
- Дистанция: z = ln(price_k/open) / (σ1m · √(N−k)), σ1m — std лог-доходностей 1m
  за предыдущие 60 минут (без заглядывания вперёд). Плюс сырая дистанция в %.
- Исход «разворот»: close окна по другую сторону от open. Равенство = проигрыш
  ставки на разворот (консервативно).
- Вывод: таблица (минут до конца × корзина |z|): n, развороты, p, 95% Wilson CI,
  безубыточный кэф 1/p, рядом гауссова «честная» p = Φ(−|z|) — так видно, где
  хвосты толще модели, по которой площадка, вероятно, считает кэф.
- Устойчивость: первые 70% истории vs последние 30%.
- Банкролл: Монте-Карло ставок по $1 при кэфе 50 и найденной p — макс. просадка,
  самая длинная серия проигрышей, шанс слить банк заданного размера.
- Самопроверка: тест на синтетических свечах (разметка окон, исход, z).

## Продукт (проверено 2026-11-24 в веб-версии binance.com/prediction)
- Рынки predict.fun внутри Binance: `btc-up-or-down-5m`, `*-15m` и т.п.,
  доступны с ПК. Стакан ордеров, цена доли 0.01–0.99, кэф ≈ 1/цена.
  Минимальная ставка $1.
- Исход: Chainlink BTC/USDT mid-price в конце окна > в начале → Up, меньше →
  Down, равенство → 50/50. Спот Binance 1m — близкий, но не точный прокси.
- Публичные эндпоинты сайта (без ключа), база
  `https://www.binance.com/bapi/defi/v1/public/wallet-direct/prediction/`:
  - `web/market/event/detail` POST `{"eventSlug":"btc-up-or-down-5m","startDate":<ms начала окна>}`
    → описание окна, marketId/tokenId (работает и для прошедших окон);
  - `msite-web/order-book` POST `{"marketId":..,"tokenId":"..","vendor":"PREDICT_FUN"}`;
  - `msite-web/order-book/last-trade-price` POST `{"marketId":..}`;
  - `crypto/price-history` POST (параметры не выяснены);
  - живые обновления через websocket (`ws/pre-subscribe`), не разбирался.
  Это внутренний API сайта, недокументирован, может измениться.

## Часть 2 — `cmd/predictrec` (запись коэффициентов)
- На каждое окно 5m/15m: `event/detail` → marketId и tokenId Up/Down; затем
  каждые 1–2 с `order-book` по обоим токенам: время, окно, open-цена, спот,
  лучшие ask/bid и объём на 0.01–0.03 → CSV. Только чтение, без ставок.
- Важно для гипотезы: при 50x покупаешь ask по 0.02 — пишем, есть ли там
  реальный объём хотя бы на $1.
- После нескольких дней записи — склейка с Частью 1: implied p площадки vs
  реальная p в том же состоянии = реальное преимущество с учётом спреда.

## Ограничения
- Ставка $1. Ключ API не нужен: Часть 2 использует только публичные эндпоинты.
- Комиссия: `event/detail` отдаёт `feeRateBps=200` (2%), `slippageBps=1000`.
  База начисления (ставка или выигрыш) не выяснена — в расчётах берём 2% худшим образом.
- `event/detail` по прошедшему окну отдаёт `status=RESOLVED`, победителя
  (`outcomes[].winner`) и `timeline[150]` — можно сверить нашу разметку исходов
  по спот-свечам с реальными исходами Chainlink.

## Оставлено исполнителю
Границы корзин |z|, формат таблицы, число прогонов Монте-Карло.

## Проверено вживую (2026-11-24, 18:20–18:55 UTC, веб binance.com/prediction)
- Комиссия 2% берётся с выплаты: Down по $0.08, ставка $1 → «к выигрышу 12.25» = 12.5 доли × 0.98.
- Целевая цена окна = open минутной свечи спота Binance (±$0.01) — исходы по спот-свечам надёжны.
- Сборщик совпадает со страницей до цента (спот и цены долей).
- Под самый конец окна дальняя сторона переоценена (−46 за 52 с: Up $0.10 при исторических ~4–5%).

## Время суток / день недели (cmd/predict, зона |z|≥2, ≥2 мин до конца)
- 12–15 UTC (открытие США, макро-данные 12:30/13:30): разворотов ×1.4–1.8 к среднему по таблице,
  во всех 4 рядах (BTC/ETH × 5m/15m) и в обеих половинах истории.
- 15–20 UTC: ×0.4–0.6 — торговать там хуже.
- Дни недели — слабо, суббота чуть выше (×1.1–1.5), нестабильно.
- `cmd/predict -rec` теперь делит результат записи на «все часы / 12–15 / 15–20 UTC».

`deploy/predictrec-cloudrun.sh`: Cloud Run, 1 постоянный инстанс, CSV по часам в бакет GCS

## Предложения 1–2 (2026-11-24)
- Поправка на час: по 24 часам — переобучение (лог-лосс на последних 30% хуже). По 3 группам
  (12–15 / 15–20 / прочие UTC) — лучше во всех 4 рядах. В 12–15 UTC на проверочной части
  разворотов 56/116/41/69 против ожидаемых без поправки 33/52/29/38. Оговорка: границы групп
  выбраны глядя на всю историю — лёгкая утечка.
- `-rec`: MaxAsk 0.15, p модели с поправкой на группу часов, отчёт окно × цена × минут до конца,
  отдельно итог в 12–15 UTC. Первые ~45 мин записи: цены площадки близки к модели (рынок не наивный).
